# מפרט טכני: התראת יתרה נמוכה (Low Balance Alert)

מסמך אפיון לתרגיל 1 בפלייבוק הבודקים. צרפו אותו ל-Agent ב-Cursor וג'נרטו ממנו תסריטי בדיקות.

**מוצר:** FinDash (דשבורד חשבונות ותנועות)  
**פיצ'ר:** התראת יתרה נמוכה  
**גרסה:** 1.0 (הדרכה)  
**קהל יעד לתרגול:** בודקים ידניים

---

## 1. סיפור משתמש

בתור **לקוח שמנהל חשבון ב-FinDash**,  
אני רוצה **לקבל התראה כשהיתרה יורדת מתחת לסף שהגדרתי**,  
כדי **להימנע ממשיכות כושלות ולתכנן הפקדה בזמן**.

---

## 2. היקף

### בתוך ההיקף
- הגדרת סף יתרה נמוכה **לכל חשבון בנפרד**
- באנר בתוך האפליקציה במסך פרטי החשבון
- שליחת מייל אופציונלי לכתובת המשתמש (אם הופעל)
- כיבוי / הפעלה של ההתראה לחשבון
- ערך ברירת מחדל לסף חדש

### מחוץ להיקף (Non-goals)
- SMS / Push notifications
- המרת מטבע בין חשבונות במטבעות שונים
- התראות ברמת "כל החשבונות יחד"
- שינוי לוגיקת חישוב היתרה עצמה (רק צריכת היתרה הקיימת מה-API)

---

## 3. כללים עסקיים

| מזהה | כלל |
|------|-----|
| BR-01 | סף ההתראה חייב להיות מספר גדול מ-0 (`threshold > 0`). |
| BR-02 | אם `balance < threshold` וההתראה **מופעלת**, מוצג באנר במסך החשבון. |
| BR-03 | אם `balance == threshold` (שווה בדיוק), **לא** מוצג באנר (רק מתחת לסף). |
| BR-04 | אם `balance > threshold`, הבאנר מוסתר (או לא מוצג). |
| BR-05 | באנר אחד לכל session דפדפן: אחרי סגירה ידנית של הבאנר, הוא לא חוזר באותו session גם אם היתרה עדיין נמוכה. ברענון מלא / session חדש: הבאנר יכול לחזור. |
| BR-06 | אם קריאת היתרה נכשלת או מחזירה שגיאה / מצב "לא ידוע", **אין** להציג באנר התראה. |
| BR-07 | רק **בעל החשבון** (owner) יכול לשנות סף / להפעיל / לכבות. משתמש עם הרשאת צפייה בלבד רואה באנר (אם רלוונטי) אך לא את מסך ההגדרות. |
| BR-08 | סף ברירת מחדל לחשבון חדש / בהפעלה ראשונה: `500` ביחידות המטבע של החשבון. |
| BR-09 | הסכומים בבאנר ובהגדרות מוצגים במטבע החשבון ובפורמט מספרי קריא (למשל `1,250.00 ILS`). |
| BR-10 | מייל אופציונלי נשלח לכל היותר **פעם אחת ליום קלנדרי** לכל חשבון, גם אם היתרה נשארת מתחת לסף. |

## 4. תנאי קבלה (Acceptance Criteria)

| מזהה | תנאי |
|------|------|
| AC-01 | במסך פרטי חשבון קיים בלוק "התראת יתרה נמוכה" עם שדות: סף, מתג הפעלה, מתג "שלח גם מייל". |
| AC-02 | שמירת סף לא חוקי (`<= 0`, ריק, לא מספרי) נחסמת עם הודעת שגיאה ברורה, והערך הקודם נשמר. |
| AC-03 | כאשר ההתראה מופעלת ו-`balance < threshold`, מוצג באנר אדום/כתום בראש מסך החשבון עם הטקסט: היתרה נמוכה מהסף שהוגדר, כולל היתרה הנוכחית והסף. |
| AC-04 | כאשר `balance >= threshold`, הבאנר אינו מוצג. |
| AC-05 | לחיצה על "סגור" בבאנר מסתירה אותו עד סוף ה-session (BR-05). |
| AC-06 | כיבוי ההתראה מסתיר את הבאנר מיד, גם אם היתרה מתחת לסף. |
| AC-07 | משתמש שאינו owner אינו רואה את בלוק ההגדרות; ניסיון קריאה ל-API של עדכון הגדרות מחזיר `403`. |
| AC-08 | כש-API היתרה מחזיר שגיאה, אין באנר ואין שליחת מייל. |
| AC-09 | אם "שלח גם מייל" מופעל והתנאי לבר-02 מתקיים, נשלח מייל (בסביבת הדרכה: נרשם בלוג / mock) עם נושא וגוף שכוללים מזהה חשבון, יתרה, וסף. |
| AC-10 | מייל שני באותו יום קלנדרי לא נשלח (BR-10). |
| AC-11 | חשבון ללא תנועות: היתרה = יתרת פתיחה; ההתראה מתנהגת לפי BR-02..04 מול יתרת הפתיחה. |
| AC-12 | אחרי משיכה שמורידה את היתרה מתחת לסף, רענון מסך החשבון מציג באנר (אם ההתראה מופעלת והבאנר לא נסגר ב-session). |

## 5. ממשקים (API): ברמת אפיון

### GET `/api/accounts/:id/alert-settings`
מחזיר:
```json
{
  "accountId": "acc-1001",
  "enabled": true,
  "threshold": 500,
  "emailEnabled": false,
  "currency": "ILS"
}
```

### PUT `/api/accounts/:id/alert-settings`
גוף בקשה:
```json
{
  "enabled": true,
  "threshold": 750,
  "emailEnabled": true
}
```
- `400` על סף לא חוקי  
- `403` למי שאינו owner  
- `404` לחשבון לא קיים  

### התנהגות מול יתרה
הלקוח קורא ל-`GET /api/accounts/:id/balance` הקיים. אין endpoint חדש לחישוב התראה בצד הלקוח בלבד: ההחלטה אם להציג באנר היא ב-frontend לפי settings + balance.

## 6. הערות UI

- באנר בראש מסך פרטי החשבון, מעל רשימת התנועות.
- כפתור "סגור" (X) בצד הבאנר.
- בלוק הגדרות מתחת לסיכום היתרה, עם שמירה מפורשת (כפתור "שמור").
- מצבי ריק: אין צורך במסר מיוחד כשאין תנועות, מעבר להתנהגות AC-11.

---

## 7. מקרי קצה וסיכונים לבדיקה (חובה לכסות בתרגיל)

1. **סף = יתרה בדיוק** (BR-03): אין באנר.  
2. **סף קרוב מאוד ליתרה** (הפרש של 0.01 במטבע עם שתי ספרות אחרי הנקודה).  
3. **שתי משיכות מהירות ברצף** ואז רענון: הבאנר משקף את היתרה העדכנית.  
4. **חשד ל-UI ישן (stale):** אחרי כיבוי ההתראה וניווט חזרה למסך בלי רענון מלא, ודאו שהבאנר לא נשאר מוצג מ-cache של הקומפוננטה.  
5. **הרשאות:** viewer מול owner.  
6. **כשל יתרה:** סימולציה של 500/503 מ-balance API.  
7. **מייל כפול באותו יום.**  
8. **הפעלה ראשונה:** סף ברירת מחדל 500 מופיע לפני עריכה.

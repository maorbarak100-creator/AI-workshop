תוכן מעוצב לפלייבוק: יצירת מייל סטטוס בדיקות יומי/דו-יומי (בשלוב MCP)
יחידה חדשה בפלייבוק: אוטומציה של דיווח סטטוס בדיקות
כרטיס תרגיל: יצירת מייל סטטוס מסבב הבדיקות ל-Outlook
מטרה ראשית: יצירת מייל סטטוס יומי או דו-יומי המסכם את תמונת מצב הבדיקות העדכנית מסבב הבדיקות המתקחש ב-Azure DevOps (ADO). 
🛠️ עבודה מקדימה (Setup & Integration)
•	התאמת MCP ל-ADO: כתיבה או הגדרת MCP ל-Azure DevOps שיודע לשלוף שדות מסוימים מתוך הפרויקט הנדרשים לצורכי הצגת הסטטוס (על סמך אפיון של ריקי). 
•	התאמת MCP ל-Outlook: כתיבה או הגדרת MCP ל-Outlook לבניית תוכן המייל ויצירת טיוטה לעיון הבודק (קיימות דוגמאות טובות). 
•	דגש בטיחות: ללא שליחת המייל בפועל! הפעולה נעצרת בשלב יצירת הטיוטה עקב הצורך בבקרת הבודק והזנת הנמענים ידנית. 
📋 סקירת הצעדים בתרגיל
#	שלב	תיאור
1	ניסוח פרומפט / הגדרת Agent	ניסוח בקשה מקיפה הכוללת את שם ה-MSP, ה-TestPlan, ודוגמת איכות למייל תקין 
2	שליפת נתונים וג'נרוט טיוטה	הסוכן מושך נתונים מ-ADO, מפרמט לפי התבנית ומייצר טיוטה ב-Outlook (או בממשק Copilot) 
3+	משוב וטיוע הדרגתי (Iterative)	ביצוע תהליך היזון חוזר מול הפלט עד לקבלת תוצאה מיטבית 
📝 פירוט הצעדים והנחיות לתרגול
צעד 1: ניסוח פרומפט ב-Copilot / כתיבת סוכן לדיווח סטטוס
1.	פתחו את Copilot או את חלונית ה-Agent ב-Cursor. 
2.	הזינו פרומפט מפורט המגדיר את משימת הדיווח:
"צור מייל סטטוס בדיקות מעודכן עבור סבב הבדיקות הנוכחי ב-Azure DevOps.
o	שם חבילת העבודה (MSP): [הכנס שם MSP]
o	שם תוכנית הבדיקות (TestPlan): [הכנס שם TestPlan]
אנא שלוף את הנתונים העדכניים ביותר מ-ADO בעזרת ה-MCP."
3.	במידה ואין MCP ל-Outlook: צרפו לפרומפט דוגמת איכות (Few-Shot Example) המדגימה איך מייל סטטוס תקין ומעוצב אמור להיראות (כותרות, טבלאות סיכום, חלוקה לבאגים פתוחים/סגורים, וכו'). 
צעד 2: הרצת ה-Agent, שליפת הנתונים וג'נרוט הטיוטה
1.	אשרו לסוכן להריץ את ה-MCP המחובר ל-ADO כדי למשוך את תמונת המצב (כמות טסטים שעברו/נכשלו, באגים פתוחים לפי חומרה, קצב התקדמות). 
2.	הסוכן יפרמט את הנתונים שנשלפו בהתאם לתבנית/לדוגמה שהוגדרה. 
3.	יצירת התוצר:
o	אם מוגדר MCP ל-Outlook: הסוכן ייצר אוטומטית טיוטה (Draft) בתיבת ה-Outlook שלכם בלבד (ללא שליחה!). 
o	אם אין MCP ל-Outlook: הסוכן יציג את תוכן המייל המעוצב ישירות כחלק מממשק ה-Copilot, מוכן להעתקה. 
צעד 3 והלאה: תהליך היזון חוזר (Feedback Loop) עד לתוצאה מיטבית
1.	סקרו את הטיוטה שנוצרה ב-Outlook או בחלונית ה-Copilot. 
2.	בצעו התאמות ושיפורים בדיאלוג מול הסוכן:
"הדגש בטבלה את הבאגים הקריטיים שנפתחו היום", "קצר את פסקת הסיכום הניהולי", או "הוסף התרעה על חסימה (Blocker) בתרחיש X".
3.	חזרו על התהליך עד שמידע הסטטוס מדויק, ברור ומוכן להפצה. 
💡 מה למדנו? (Takeaway)
•	אוטומציה בטוחה (Human-in-the-loop): השימוש ב-MCP מאפשר חיבור ישיר למידע בזמן אמת מ-ADO, אך עצירת התהליך בשלב ה-Draft ב-Outlook מבטיחה בקרת איכות אנושית לפני שליחה. 
•	אחידות ואיכות בדיווח: הגדרת תבניות ודוגמאות איכות בפרומפט מייצרת סטנדרט אחיד לדיווח הסטטוס בצוות הבדיקות, וחוסכת זמן איסוף נתונים ידני בכל סוף יום

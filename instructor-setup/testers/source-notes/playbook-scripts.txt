תוכן מעוצב לפלייבוק: ג'נרוט תסריטי בדיקות מתוך אפיון טכני ל-ADO

יחידה חדשה בפלייבוק: תרגול QA ו-Copilot כרטיס תרגיל: ג'נרוט תסריטי בדיקות בהתאם לאפיון הטכני

מטרה: לג'נרט תסריטי בדיקות מקיפים מתוך מסמך אפיון טכני, לטייב אותם בדיאלוג, ולהפיק קובץ תבנית (אקסל) מוכן ליבוא ישיר לתוך Azure DevOps (ADO).
📋 סקירת הצעדים בתרגיל
#	שלב	תיאור
1	הפעלת Copilot וניסוח פרומפט ראשוני	ג'נרוט תסריטי בדיקות מנגזרת של האפיון הטכני (כולל שדות חובה ל-ADO)
2	המשך שיח (Iterative Refinement)	סשן טיוב התוצאה ובחינת כיסוי האפיון עד לכיסוי מלא של התכולה
3	ניסוח פרומפט לכתיבת התסריטים	המרת הפלט לפורמט תבנית מבנית (אקסל) המתאימה ליבוא ל-ADO
4	ייבוא האקסל לתוך ה-ADO	העלאת הקובץ למערכת Azure DevOps ליצירת התסריטים בפועל
📝 פירוט הצעדים והנחיות לתרגול
צעד 1: הפעלת Copilot וניסוח פרומפט לג'נרוט ראשוני
1.	פתחו את Copilot וצמדו/צרפו את מסמך האפיון הטכני.
2.	הזינו פרומפט לג'נרוט תסריטי בדיקות הכולל דרישה מפורשת לשדות הנדרשים כחלק מטעינה ל-ADO:
"קרא את מסמך האפיון הטכני המצורף. ג'נרט רשימת תסריטי בדיקות (Test Cases) המכסים את כל הלוגיקה העסקית. עבור כל תסריט, כלול את השדות הבאים: Title, Description, Pre-Conditions, Steps, Expected Result, Priority, ו-Automation Status."
3.	סקרו את התשובה הראשונית של Copilot.
צעד 2: המשך שיח (Session) לטיוב ובחינת כיסוי האפיון
1.	אל תעצרו בתשובה הראשונה – המשיכו את השיח באותו סשן.
2.	שאלו את Copilot שאלות ביקורתיות לבחינת כיסוי התכולה:
"אילו מקרי קצה (Edge Cases), תרחישי שליליים (Negative Scenarios) או הרשאות שמופיעים באפיון אינם מכוסים ברשימה שיצרת?"
3.	בקשו ממנו להשלים את התרחישים החסרים עד שתגיעו לכיסוי מלא ומספק של האפיון.
צעד 3: ניסוח פרומפט להמרת התסריטים לתבנית אקסל ל-ADO
1.	לאחר שהתרחישים מקיפים ומדויקים, נסחו פרומפט שממיר אותם לפורמט הנדרש ליבוא:
"מנה את כל תסריטי הבדיקות שסיכמנו והצג אותם בתוך טבלה המותאמת לייצוא ל-Excel/CSV עבור יבוא ישיר ל-Azure DevOps (ADO). שמות העמודות בטבלה חייבים להיות: Work Item Type, Title, Test Step, Step Action, Step Expected, Priority."
2.	העתיקו את הטבלה שנוצרה והדביקו אותה בקובץ Excel (או בקשו מ-Copilot לחלץ קובץ CSV/Excel אם הכלי תומך בכך).
3.	ודאו שהפורמט נקי ושמבנה השורות תואם לתבנית היבוא של ה-ADO בארגון.
צעד 4: ייבוא האקסל לתוך ה-ADO ליצירת התסריטים בפועל
1.	פתחו את פרויקט ה-Azure DevOps (ADO) שלכם ועברו ל-Test Plans (או לוח ה-Work Items בהתאם להרשאות).
2.	בחרו באפשרות Import Test Cases / Import Work Items והעלו את קובץ האקסל.
3.	בצעו Mapping (מיפוי שדות) קצר במידת הצורך, ואשרו את הייבוא.
4.	ודאו שתסריטי הבדיקה נוצרו בהצלחה במערכת ומשויכים כראוי.
💡 מה למדנו? (Takeaway)
•	תהליך מבוסס איטרציות: ה-Copilot נותן בסיס מצוין בצעד הראשון, אך הערך האמיתי נוצר בצעד 2 – בדיאלוג ובחינת כיסוי מקרי הקצה.
•	מפרומפט למוצר סופי: חיבור ה-Copilot לפורמטים ארגוניים (כמו תבנית אקסל ל-ADO) הופך את תוצר ה-AI מ"טקסט רגיל" לכלי עבודה פרקטי שמחליף עבודה סיזיפית.
•	אתם ה-Reviewer: האחריות על וידוא כיסוי האפיון והדיוק של השדות ב-ADO נשארת אצל בודק התוכנה.
